# 拼多多自动开户实施方案

批准范围：草木造物“补差价专用”的 10张、20张两个真实 SKU；所有开关默认关闭。功能只发送选图入口，实体物流由商家实际寄件时处理。

## 数据与权限

组织下的负责账户可绑定多家店铺；平台店铺全局唯一绑定。使用阿奇索电商业务应用的官方 OAuth，一次性 state 绑定账户、组织和会话，跨站回调使用短期 HttpOnly nonce；Token 用 Fernet 加密保存。组织隔离覆盖管理 API、异步任务和客户素材。

## 订单处理

1. 商品与 SKU 按真实 ID 匹配。生成及提交额度乘件数，单张重做仍为 2；上限 360，未知或冲突规则交人工。
2. 已验签的成团通知先入库再确认接收；后台任务恢复未处理记录。
3. 人工与自动开户共用服务并保存负责账户的水印、打印等快照；重复通知不重复开户，人工订单号冲突不自动接管。
4. 开户与消息分开记录。发送失败仅在供应商明确允许时有限重试；超时和进程中断的未知结果需人工核对。绝不调用物流写入接口。
5. 售后自动处理在真实事件验证前关闭；启用后独立处理退款暂停、全额取消、撤销和乱序事件。停用店铺停止新自动开户和消息发送，保留已有订单及售后保护。

## 页面与客户入口

新增店铺接入页，包含授权、商品套餐、接入订单及通知记录。测试预置填入 10/10/2 与 20/20/2，真实 ID 留空。异常提供中文提示、可安全重放或重试的操作、复制同一客户入口。

客户使用 /guest?order_number=... 预填订单号并确认进入；已有另一订单时提示切换，登录后移除地址参数。暂停订单保留水印预览并隐藏生成、重做和提交。

## 验证与上线

- 后端验证精确额度、并发去重、组织权限、授权绑定、重启恢复、发送次数、退款状态和现有客户流程。
- 前端构建及测试验证规则、入口、切换、暂停；浏览器回归水印预览、生成/重做/提交与打印。
- 配置示例保持密钥为空，售后开关为 0；启动器关闭含查询参数的访问日志。
- 应用开通、授权许可、Windows 助手、真实商品/SKU ID 和真实订单回调均为上线前置条件，不能用本地模拟代替。
