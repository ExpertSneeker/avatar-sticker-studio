## Shared decisions and API contract

Roles are `superadmin`, `org_admin`, `staff`; users have `organization_id`. Existing users/catalog/orders migrate to one organization; magnus becomes org_admin (existing admins also org_admin). Bootstrap on an empty database creates superadmin with an initial organization so existing setup-based testing and catalog use remain practical. CLI creates independent superadmin without a default password. Auth helpers `same_organization(value, actor)`, `require_admin` (org or super), `require_superadmin`; assets and uploads have organization_id, library resources scoped by organization. New customer orders are stored in records kind `orders`, flagged `workflow_version:3`; legacy orders stay supported and distinct. New tasks in `items`, owner always opener account, organization_id inherited. Generations remain recorded but new credit reservations are exempt. Existing frozen credits released only for known ended requests; unknown records retained for audit.

All customer-order routes use explicit safe DTOs, never raw records. Backend routes `/api/customer-orders`, `/api/customer-orders/{id}`; guest routes `/api/guest/login` ({order_number}), `/api/guest/logout`, `/api/guest/order` (current), `/api/guest/library` ({stickers,templates}), `/api/guest/uploads/init`, `/api/guest/uploads/{id}` (GET/PUT), `/api/guest/uploads/{id}/complete`. Guest cookie distinct from staff, HTTPOnly; login persists throttling, no plaintext order numbers in URLs. Staff uploads reuse `/api/uploads/*` and organization sharing.

Open POST `/api/customer-orders`: {order_number,generation_limit,final_count,rerun_limit,notes,client_token}. Constraints 1<=final_count<=generation_limit<=360, rerun_limit>=0, unique global order_number forever. Watermark and print defaults snapshot opener at registration. Blank watermark falls back to opener display_name. Backend supports staff creating on behalf of customer.

Common GET order DTO: {id,order_number,state,version,generation_limit,final_count,rerun_limit,avatars,slots,preview_url,delivery_ready,created_at}. Staff additionally {owner,owner_name,notes,organization_id,watermark,print_settings,delivery_version}. States `draft`, `review`, `submitted`, `cancelled`; processing status per item. avatars: {id,name,preview_url}; slots: {id,avatar_id,sticker_code,status,reruns_used,reruns_reserved,selected_version_id,pending_version_id,versions:[{id,preview_url}],error?}. Guest error messages generic. Guest submitted DTO must omit avatars/slots, only safe summary+overview; cancelled DTO minimal id/order_number/state. No original URLs/notes/provider details in guest DTO, including uploads.

Mutations POST suffixes on `/api/customer-orders/{id}` and `/api/guest/order`: `/preflight`, `/generate`, `/slots/{slot_id}/rerun`, `/slots/{slot_id}/select`, `/submit`. Bodies common {client_token,expected_version}; generate/preflight also {avatars:[{upload_id,template_ids:string[],sticker_ids:string[]}]} (arrays allow repeats; avatar upload record cannot be duplicated). select also {version_id}; submit also {slot_ids:string[]} whose order is final print order. Preflight returns {avatar_count,selection_count,generation_count}, does not mutate. Every mutation checks ownership, optimistic version, and idempotency payload fingerprint; identical token repeat returns current representation before stale-version check. Selection total F..G, avatar count 1..F; first generate freezes all choices. Initial generation dedup within order by avatar record + sticker_id + revision. Slots independently point at immutable result versions; each rerun creates its own task, does not mutate shared initial task. Successful reruns require choosing old vs new (pending_version_id); count consumed even if discarded. Definitive failure releases reserved rerun; unknown keeps hold; no submit while pending jobs or pending version choices. Server recovery does not double count.

Staff-only POST `/{id}/cancel`, `/restore`, `/unlock`, `/repack` use same mutation body. All org staff may perform. Cancel remembers prior state, denies old guest image links, stops new requests/publishing, lets submitted remote calls reconcile. Restore returns prior state; unlock submitted->review, keeps spending/history, invalidates deliverables until resubmit. All actions audited. Publish only submitted orders, freezes chosen slot-version-order transactionally, worker publishes selected originals automatically and idempotently; notes never in preview. New artifacts/manifest/ZIP contain print pages only; overview tracked separately. GET `/{id}/manifest`, `/{id}/download.zip` reject non-submitted/cancelled/not-ready.

POST `/api/customer-orders/watermarks/preview`: {ids} -> {orders:[{id,order_number,watermark}],preview_token}. POST `/api/customer-orders/watermarks`: {ids,preview_token,client_token} -> {updated:number}; validates selected org subset and settings fingerprints. Uses each opener current watermark/display_name, updates snapshot/version and re-renders previews only (no generation, originals unchanged); old guest preview URLs invalid immediately. Cancelled remains inaccessible.

Guest media is a separately authorized endpoint, never legacy /assets preview. Cache key includes asset revision/hash, opener id, watermark content/version, size, render pipeline. Server flatten+heavy diagonal tiled watermark, no-store, no original fallback. Authenticate before cache use and recheck cancel/version before returning bytes. Source avatar previews also protected. No guest image persistence/download/directory code. All order/item/version historical references protected from cleanup.

Frontend entry `/guest` loaded separately from staff shell. Staff landing workspace becomes customer order creation/list/workbench with original legacy orders still accessible in a separate legacy view. Both guest and staff share workflow UI via explicit mode/base URL but guest only uses safe guest DTOs. Upload avatars, repeated quantities, preflight+generate, poll, old/new comparison and exact final count. Order screen filters opener, date, order number, state incl recycle bin. Org staff can cancel/restore/unlock and bulk watermark preview/apply. Remove all automatic save effects and draft directory binding. Manual batch download root picker, folders sanitized order_number + '_' + notes (no notes => order_number), hash check, no overwrite foreign files; fallback ZIP. Backend manifest authoritative only print files; legacy manifest also filtered print. Account settings keep watermark/print defaults; remove Credits everywhere. Org admin account management; superadmin organization management + global settings/statistics. Organization API `/api/admin/organizations` GET/POST {name,admin_username,admin_display_name}; POST returns {organization,admin,temporary_password}; PATCH `/{id}` {name?,active?}; org admin can manage only same-org accounts. Superadmin global settings only. User DTO `organization_id`, `organization_name`.
