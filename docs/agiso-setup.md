# 拼多多自动开户：草木造物配置与验收

本功能给实体贴纸订单开通网站选图额度，并向客户发送选图链接。不会调用无需物流发货、自动核销、退款支付或快递接口。实际寄件仍由商家在拼多多完成。

## 当前交付与外部前置条件

代码支持店铺授权、商品/SKU 额度、订单推送入库、自动开户、消息发送及有条件的售后处理。首次上线必须先配置应用；应用未配置、店铺未授权或开关关闭时，不自动开户或发送消息。

2026-09-18 核对：草木造物已授权“贴纸”应用（交易确认、交易成功、退款创建、退款成功、买家备注修改、售后单关闭六类推送），发送助手在线，测试商品“树脂纽扣多色多规格衣服缝纫手工DIY辅料扣子”（商品 ID 1004761806324）已配置 A-10、A-15、A-20 三个规格并绑定含订单号和预填链接的消息模板，网站端店铺开关已开启。阿奇索店铺服务到期日为 2026-09-21，需在拼多多服务市场续费，否则会影响消息发送。真实订单的付款后推送字段、自动开户和消息发送仍待首单验收。

本次浏览器策略禁止访问拼多多商家后台和“我的服务”；不能据此认定商品未上架。开放平台开发者应用、权限、实际助手在线状态和真实订单推送仍需要店主配合验证。

## 第一步：开通开发者应用（网站管理员）

1. 在 https://open.agiso.com/ 登录开发者账户，完成个人或企业认证。
2. 创建“电商业务”应用，由网站统一承担接口费用；不是为每个店主创建托管应用。
3. 联系阿奇索客服开通拼多多权限。推送：交易确认（客服确认付款后即推送，不要求成团）、交易成功、退款创建、退款成功、买家备注修改、售后单关闭；接口：商品列表、消息发送、开放平台余额查询。不要申请自动退款、物流写入或“获取最近一笔发送的卡密”（慎选项）。
4. 设置授权回调为 `https://sticker.magnusma.online/api/agiso/callback`，推送地址为 `https://sticker.magnusma.online/api/agiso/webhook`。
5. 向客服确认：推送成功应答格式、重试节奏/次数、重复推送计费、拼多多售后 topic 与 operation 对应关系、全额和部分退款识别方式。

官方资料：
- [创建应用](https://www.agiso.com/detail/1552)
- [多店授权与费用归属](https://www.yuque.com/agiso/open/owplxcrlyxpzw1cq)
- [拼多多接入协议](https://open.agiso.com/document/#/aldsPdd/guide)

不得把 AppSecret、店铺 Token、验证码或加密密钥粘贴到聊天、工单或 Git。认证及权限授予由账户持有人完成。

## 第二步：部署服务器配置（网站管理员）

安装本次 `uv.lock` 对应依赖（新增 cryptography）。在服务器私密环境文件 `/etc/avatar-sticker-studio.env` 设置：

| 变量 | 内容 |
| --- | --- |
| `STUDIO_AGISO_APP_ID` | 开放平台应用 ID |
| `STUDIO_AGISO_APP_SECRET` | 该应用密钥 |
| `STUDIO_AGISO_ENCRYPTION_KEY` | Fernet 加密密钥，固定保存；改变后旧店铺凭证无法解密 |
| `STUDIO_AGISO_PUBLIC_URL` | 网站 HTTPS 根地址，不包含路径、参数或尾随业务路由 |
| `STUDIO_AGISO_AFTERSALES_VERIFIED` | 首次必须为 `0`；2026-09-18 已按真实退款通知验收并改为 `1`，停止自动售后时可改回 `0` |

加密密钥在受控服务器终端生成并写入私密文件，勿输出到共享会话。使用 `cryptography.fernet.Fernet.generate_key()` 生成；环境文件权限为 0600。升级时保留真实数据库和密钥，不覆盖成开发测试数据。

授权回调采用一次性 state + code 换 Token，网站不会要求员工手输店铺 Token。凭证失效时重新授权同一店铺。店铺不能跨组织/账户重复绑定。

默认服务单元和本地启动器已关闭 Uvicorn access log，避免记录带订单号的查询参数和授权 code。若使用其他启动命令，也应加 `--no-access-log`。应用返回 `Referrer-Policy: no-referrer`，前端 HTML 同时设置该策略。Cloudflare/其他代理的日志与分析采集需检查，不得保存完整 `/guest?order_number=...` 或 OAuth 回调查询参数；不能只依赖登录后清理地址栏。

## 第三步：连接草木造物（店主）

1. 使用网站中需要负责草木造物订单的账户登录。
2. 打开“店铺接入” → “连接拼多多店铺”。
3. 在阿奇索页面确认正在授权的店铺是草木造物，完成授权后回到网站。
4. 检查店铺名称、负责账户、授权到期时间。自动开户仍应关闭。

店铺所属账户及本组织管理员可以配置，其他同组织员工仅查看。自动订单继承负责账户当前的水印、打印参数并形成快照。

## 第四步：设置发送助手（店主）

按[官方无卡券教程](https://www.yuque.com/agiso/aldspdd/bw2go6)安装官方拼多多发送助手并登录。正式运行使用专用 Windows 云主机保持在线，购买前确认官方当前支持的系统和资源要求。

官方说明助手需要持续在线；不要直接套用淘宝的代挂服务流程。客服工作台与助手的共存、账号登录方式按拼多多助手说明操作。

本系统在开户成功后通过消息接口发送入口。不要另外配置同一商品的相同自动消息，不要勾选“无需物流发货”或自动核销。若推送必须启用某个商品设置，先与客服确认仅通知、不改变实体订单物流状态的配置。

[消息接口](https://open.agiso.com/document/#/aldsPdd/api/sendMsg)限制每笔订单 30 天内最多 5 条。本系统更保守地限制每单最多 5 次发送尝试；明确允许重试的失败自动重试最多 3 次，其后仅在后台允许的情况下人工重试。超时、发送进程中断等不确定结果不自动补发，应先在拼多多聊天窗口核对。

## 第五步：配置测试商品

仅使用“补差价专用”商品，不启用其他在售商品，也不设置全店默认开户。

1. 在“商品套餐”中使用“手动添加”逐条配置，或从店铺选择规格。
2. 点击“从店铺选择规格”，搜索“补差价”，分别选择准确的两个规格，填入真实 ID；或从经核对的商家信息手动填写 ID。
3. 按下表核对，保存；逐条启用这两个 SKU，其他 SKU 不启用。
4. 助手和应用均准备完成后，再开启这家店铺的自动开户。

| 规格 | 每件可生成 | 每件最终提交 | 整单重试 |
| --- | ---: | ---: | ---: |
| 10张 | 10 | 10 | 2 |
| 20张 | 20 | 20 | 2 |

“20张”购买 2 件得到 40/40/2，重试次数为整单共用、不乘件数。最多 360 张。多个订单条目重试规则不一致、缺失映射或总量超限时转人工，不猜额度；与人工创建的订单号冲突时也不自动接管。

一键测试套餐功能已移除，需逐条设置真实商品和 SKU ID。选择其他规格时必须人工核对其额度，系统不会从标题解析数量。

## 第六步：逐项验收

在启用前保存实际联调记录（日期、商品/SKU ID、实际订单号仅保存在受限记录中，消息截图脱敏）。创建真实订单、付款和退款由测试人员在拼多多操作。

- 10张 × 1：生成/提交 10，整单重试 2。
- 20张 × 1：生成/提交 20，整单重试 2。
- 20张 × 2：生成/提交 40，整单重试 2。
- 未成团不开户；成团后“接入订单”出现一条，重复通知不重复开户。
- 消息包含 `/guest?order_number=...`。客户点击后订单号预填，点击进入；成功后地址栏清理参数。
- 浏览器已有另一个订单时，先提示切换，不展示错误订单工作台。
- 客户完成选图、生图、整单共用两次重试、准确数量提交；只能访问水印预览。
- 商家下载打印文件，拼多多物流仍未因选图入口消息被标记发货。
- 发送助手离线时检查“消息状态”，恢复后只对允许重试的记录重试；不确定结果先人工核对。
- 临时授权失效应显示待处理原因，重新授权后自动继续处理等待中的通知和消息，不能重复开户。

验证内容包括退款申请、全额成功、撤销/驳回、部分退款、退款先于订单推送、多笔售后及乱序通知。退款处理中停止新的生成、重试与提交，已有远程生图可能完成，结果继续受权限限制。确认整单退款成功才取消客户访问；部分退款及换货/补寄等转人工。

退款撤销只解除该售后的暂停原因，不能恢复已取消订单或清除人工暂停。2026-09-18 已依据真实退款通知将 `STUDIO_AGISO_AFTERSALES_VERIFIED` 设为 `1` 并重启服务；如需紧急停止自动售后，改回 `0` 后重启即可，退款通知仍会记录。

## 日常异常处理与停用

“接入订单”分别显示开户、消息发送、客户进入时间；“通知记录”显示原因。修正 SKU 规则后，使用记录中的“重新处理”恢复可重放事件；已开户订单不会重复创建。消息未知时复制同一选图链接给人工客服使用，不在网页上反复点击重试。

关闭店铺开关会停止新订单自动开户和消息发送，保留已开户订单、生成结果及记录；已验证的售后保护仍会暂停或取消相关已有订单，其他客户订单继续按现有流程处理。没有通用订单补拉保障：如平台漏推，人工核对后沿用“开新订单”。不得用未经核验的请求伪造真实支付订单。

截至 2026-09-18，应用配置、店铺授权与发送助手已就绪，但真实订单的推送接收、自动开户和消息发送仍未完成首单验收。未自动处理的推送类型（交易成功、买家备注修改等）只记录到“通知记录”，显示“已忽略”。
