# AI 头像贴纸工作台

本机运行的内部生产网站：批量头像和模板套装、生图队列、透明打印排版、中文水印总览、结果检查、账号和管理设置。

## 启动

需要 Node.js 22.12+、npm 和 uv。首次安装依赖：

```sh
npm run setup
```

日常启动：

```sh
npm start
```

打开 **http://127.0.0.1:8000**。在终端按 Ctrl+C 停止服务。命令只监听本机，不部署到服务器。

开发时使用 `npm run dev`，页面地址为 http://127.0.0.1:5173。修改后端代码后重新启动开发命令；前端自动刷新。可复制 `.env.example` 为 `.env` 调整端口、数据目录或水印字体。

## 第一次使用

1. 创建管理员账号；此入口只在尚无账号时出现。
2. 在「管理设置」填写网站专用 FAL API Key 并保存。旧 OpenAI 密钥不会被当作 FAL 密钥使用。密钥保存后只显示配置状态；留空不会覆盖原密钥。缺少密钥时任务保持排队。
3. 在「模板库」新建套装：填写唯一编号、名称和男孩／女孩／动物／通用分类，上传 1–100 张图片；按文件名自然排序后可逐张调整顺序。编辑生成新版本，旧订单继续使用原版本和张数。模板库及下单选择器支持空格多词搜索，例如 `A1 13` 可匹配 `A1-13`；多个词均需匹配，忽略大小写与多余空格。水印总览每套单独起行，每行 4 张，末行不足 4 张留白。
4. 在「账号设置」填写水印文字和常用打印参数。留空水印使用显示名称。
5. 在「工作台」上传头像，在“图片名称／保存文件夹名”中编辑名称，默认使用不含后缀的图片名；逐单或批量选择套装和打印参数。等待「草稿已保存」后，未提交内容可在刷新或重新打开页面时恢复。
6. 先选择本机全局输出目录；每个订单也可单独选择保存位置，默认跟随全局目录。所选订单没有保存目录时不能提交。提交时固定各订单目录，之后更换全局目录不会改变旧订单。任务中心分别显示服务器进度与本机保存状态；可继续添加其他订单。

上传前会在浏览器本地按短边 1024 px 等比缩小头像和新增／替换的模板；短边不超过 1024 px 时不放大，PNG／WebP 保留透明通道，原始本机文件保持原样。服务器接收处理后的图片，既有模板和结果不会批量改写。

选择模板弹窗支持按名称或编号搜索（不区分大小写），逐单与批量选择都可用。搜索隐藏套装时仍保留已有选择，可清空搜索继续查看。

需要新增制作成员时，在管理设置生成邀请码。邀请码七天有效、只能使用一次。成员只访问自己的订单和文件；管理员可以管理账号与公共模板。API 接口也校验账号归属和当前页面预期账号，避免多标签页切换账号后误提交。

## 生成、检查与恢复

- 通过 FAL 队列调用 `openai/gpt-image-2/edit`，使用 FAL 账号和密钥；固定 `low`、`1024×1024`、透明 PNG、每次一张，模板在前、头像在后。无需 OpenAI API Key。
- 每套按实际图片数产生独立任务，每个订单最多 360 张；积分冻结及结算按实际张数计算。管理设置仅保留「最大同时处理数量」，默认 2，可设 1–40；不配置每分钟生图数量。网站所有账号共用上限，包含已提交、在 FAL 排队和正在处理的任务。FAL 账号本身另有跨应用共享的实际并发上限，达到时由 FAL 排队等待。
- 默认 A4、300 DPI、单张透明内容长边 85 mm、10 mm 页边距和间距。亮度和色彩平衡默认关闭。
- 「结果检查」对照原头像、固定模板、当前结果；单张重跑仅生成这一张，成功后更新所属套装和总览。失败保留旧结果。
- 已生图但抠图失败时，配置抠图服务后点击「仅重试后处理」，复用已保存原始结果。它不会再次调用 FAL 生图。
- 「重新排版」只处理已有图片；修改账号水印后，打开需要更新的订单点击「更新水印」，打印文件保持原样。
- 暂停影响尚未开始的任务。关闭网页后，本机后端进程继续处理；关闭终端或电脑会停止服务。重启恢复排队任务；已取得 FAL 请求编号的任务继续查询同一个请求，结果下载失败也重新取回原结果。已发送但没有取得编号的未知请求不会自动重发。
- 单张结果显示 FAL 排队／生成状态和请求编号。连接异常时优先恢复原请求；「重新生成」会产生新的计费请求，尚未确认结束的 FAL 请求不能直接重跑。

## 文件保存

创建新订单需要桌面 Chrome／Edge 选择并授权保存目录。不支持目录授权的浏览器仍可查看已有订单并在详情下载 ZIP；ZIP 保留相同目录结构。

```text
输出根目录/
└── 小满/
    ├── 小满_B001_1.png
    ├── 小满_B001_2.png
    └── 小满_水印总览.png
```

套装独立排版、页码从 1 开始，打印 PNG 无水印，每页顶部居中标注订单名。A4 为 2480×3508 px 并含 300 DPI 元数据；打印时选择 100%／实际尺寸。

一个头像只输出一张全部套装总览：每套 4×3、每单元 256 px、多套纵向排列、白底、大字粗体中文水印，45° 密集平铺，带白色描边和阴影。订单列表缩略预览可点击打开原图弹窗。单张成品保留在服务器，可以单独下载。

网页关闭期间不能写入本机目录。全部套装及总览完成后，每个订单仅自动下载一次，完成记录保存在当前浏览器。刷新、缺失文件或后续重跑／更新水印均不会再次自动下载；在任务中心勾选订单，点击“重新下载所选订单”会先弹出目录选择窗口，一批订单只选择一次，各自保存到所选目录的订单子文件夹；取消则不下载。默认定位到首个订单最近保存的位置，新选择不改变全局或原始提交目录。可重新获取当前文件，切换回此前保存过的位置也会继续校验文件归属。首次保存中断可以继续，仍沿用校验、断点恢复和文件保护。

本地同名文件未经此订单管理时，选择其他目录；不会直接覆盖。已管理文件被修改或损坏时，订单详情的「修复此订单已管理的文件」会在确认后恢复服务器版本。更新完成且逐一校验后，才删除该订单淘汰的旧页。多标签页写入同一订单目录会串行执行。

任务中心显示提交时间，可按最近 24 小时、3 天、7 天、30 天筛选，与名称／套装搜索、状态筛选取交集。“打开目录”使用浏览器系统目录窗口定位到订单子文件夹；浏览器没有直接启动 Finder／资源管理器的标准接口。

## 数据与备份

正式数据在被 Git 忽略的 `.data/`：账号、密钥、任务、原始上传、模板版本、结果和文件清单。不会按时间自动清理素材。管理员可查看服务端磁盘总量、已用、可用和网站数据占用，并按提交时间预览清理某个日期之前的订单。清理覆盖所有账号，必须勾选永久删除确认；正在运行、结果待确认或仍占 FAL 并发的订单跳过。完整订单、单张任务及错误记录、关联成图和历史输出、拼图、总览、无其他订单共用的头像及原始上传均会删除；公共模板及全部历史版本保持原样。所选日期按当前设备时区 00:00 转为服务端时间，严格删除早于该时刻的订单。清理失败的文件保留在持久化待删清单，可重试或在服务器重启后继续。本机已下载文件保持原样。

旧版没有订单归属的历史输出，只有在可确认属于被清理范围时删除；存在其他订单、无法归属的历史输出保留并显示数量。新生成文件均记录订单归属。

账户管理支持删除普通成员账号：先预览影响数量，再输入完整用户名确认。删除其全部个人模板及历史版本、订单和错误记录、上传文件、原图、生成结果、打印拼图、总览及缩略图缓存，并立即撤销登录会话。公共模板、其他账号和本机已下载文件保持原样。管理员账号不可删除；正在处理、占用远端并发或结果待核对的任务必须先处理完。删除与积分结算在同一事务中完成，释放尚未消耗的冻结积分，仅保留不含姓名、自由备注或素材内容的最小积分流水。文件删除失败沿用管理设置的待清理重试机制。

备份时先停止应用，再完整复制 `.data/`，恢复时完整放回；不要只复制 SQLite 主文件而遗漏 WAL 或图片目录。

浏览器草稿、目录授权句柄和本机文件管理记录存储在该浏览器的 IndexedDB，按账号隔离。清除浏览器站点数据后需要重新选择目录；原有服务器结果仍保留。同名但已失去管理记录的本地文件按外来文件处理。

自动测试使用临时数据目录和注入的测试生图服务，覆盖真实上传、后台处理、排版和浏览器操作；不会污染正式账号或调用付费 API。浏览器测试使用 8001、5174 端口。

## 统计页面

侧栏「我的统计」仅汇总当前账号；管理员额外拥有「全站统计」，包含全部账号的订单及成员制作情况。后端分别通过 `/api/statistics` 和 `/api/admin/statistics` 校验权限，个人接口不能通过指定其他账号扩大范围。

支持最近 24 小时、3 天、7 天、30 天及全部订单。按订单提交时间筛选，展示这些订单当前的计划图片、完成、失败、待确认、启动尝试及模板使用情况；包含归档订单，清理订单后相关统计随之移除。趋势按当前设备时区分日，全部模式的趋势只展示含今天在内的最近 30 个自然日。模板编号和成员名称可搜索。

「追加生图尝试」是各单张首次启动之外的尝试总量，包含重跑及提交重试，不代表实际付费次数；完成率为当前完成单张除以计划图片。历史耗时、费用及跨设备下载次数暂无可靠记录，未纳入统计。统计在进入页面、切换时间或点击刷新时重新获取，避免额外持续轮询。

每个账号独立设置生图并行上限（默认 2，范围 1–40，管理员账号同样适用）。管理员在「账户管理」点击“生图并行上限”列的数量打开设置弹窗；成员在「账号设置」只读查看，页面会自动刷新最新上限。旧账号未设置时使用默认 2，不修改旧订单或素材。全站上限与账号上限同时生效，所有进程、同一账号的全部订单及重跑共用账号额度。FAL 排队中和仍保留远端占用的未知请求计入额度；已发出请求的恢复查询不重新占名额，已有图片后处理不受生图额度阻塞。调低上限不会取消在途请求，只暂停后续新请求的发起；多个管理员同时修改时拒绝覆盖已经变化的值。不增加每分钟请求数量限制。

生图采用按账号动态公平调度：优先把空位分配给当前远端占用较少的账号，占用相同时按持久化顺序轮流执行。只有一个账号有待处理任务时可用满其账号上限与全站上限中的较小值；例如两个账号各上限 20、全站 20，持续有任务时逐步均衡到各 10。新账号加入不会取消已发出的请求；在已有请求结束后获得空位。额度不足、暂停、停用或暂不可重试的任务不占用预留份额，其他账号可利用剩余空位。

打印标题使用订单原名（不使用重名任务文件夹自动增加的后缀），黑色、约 3 mm 字号、距纸张顶部 3 mm，每页一次；长名完整换行。左右与底部采用设置的基础页边距，顶部至少在基础值上增加 2 mm，并根据标题高度留足间隔；图片整体在剩余区域水平、垂直居中，保留物理尺寸、透明底与 DPI。固定图片尺寸和间距下，多余留白由居中分配，实际横向与纵向留白不一定完全相等。旧的已完成打印文件保持原样，点击「重新排版」可应用新格式，不重新调用生图；已下载订单需主动重新下载。
