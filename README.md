# AI 头像贴纸工作台

React + FastAPI + SQLite 贴纸生产网站，支持组织隔离、店铺开户、访客选图、多头像和版本对比、提交拼版及后台手动交付。旧订单、素材快照和原图继续保留。

## Agent 接手入口

先读 [AGENTS.md](AGENTS.md)。[架构与行为契约](docs/architecture-and-contracts.md)说明代码位置和业务边界，[运维指南](docs/agent-operations.md)说明安全启动、测试及发布，[交接记录](docs/agent-handoff.md)说明核对基线和仍需现场验证的内容。Claude / Gemini 的入口文件引用同一套规则。

## 启动

需要 Node.js 22.12+、npm 和 uv：

```sh
npm run setup
npm start
```

后台打开 http://127.0.0.1:8000，访客打开 http://127.0.0.1:8000/guest。在终端按 Ctrl+C 停止服务。本地命令不会部署到服务器。

开发使用 `npm run dev`，前端端口 5173；后端修改后重新启动。可复制 `.env.example` 为 `.env` 配置数据目录、端口和水印字体。正式数据默认位于被 Git 忽略的 `.data/`。

`npm start` 和 `npm run dev` 会启动真实 worker，并可能处理数据目录中的任务；数据库也可能保存服务密钥。首次接手时先检查数据目录，使用[隔离测试流程](docs/agent-operations.md)，不要在已有业务数据上试运行迁移或生图。

## 账号与组织

- 超级管理员管理组织、组织管理员、通用提示词、API 密钥、全站并发和全站统计。
- 组织管理员管理本组织成员、图库编辑授权及账号并发。
- 店铺账号协作处理本组织订单；图库编辑仍需授权。
- 访客只凭订单号进入该订单，使用独立会话和水印预览，无法访问后台及原图。

旧账号和图库迁入同一个默认组织，`magnus` 为组织管理员。已有订单名称不会变成访客登录订单号。独立超管通过服务器命令创建，无默认密码，具体见 [升级与发布说明](deploy/framework-release.md)。空数据库首次启动仍可从初始化页面创建平台管理员。

新任务不预扣积分，不设置积分余额门槛。实际生图记录、历史账本和未知请求保留。全站公平调度及每账号并发限制同时生效；访客任务计入开户账号。

## 开户与制作

1. 店铺设置账号水印和默认打印版式，在订单页面开户：填写拼多多订单号、可预览数量上限 G、最终提交数量 F、整单重试上限 R 和内部备注。约束为 `1 ≤ F ≤ G ≤ 360`、`R ≥ 0`。
2. 客户进入 `/guest` 输入订单号，或店铺打开订单代客制作。上传 1 至 F 个头像，各自选择模板或贴纸，可设置重复份数。
3. 生成前查看份数和实际任务数，确认后冻结头像、素材版本及选择。相同头像和贴纸版本的首次生成去重，重复份数分别占名额。
4. 每份可独立重做，对比并保留旧版或新版，但所有份数共用整单 R 次机会。成功重做消耗一次，保留旧版也不退回；明确失败退回，未知结果保留占用并由后台核对。
5. 所有任务及版本选择结束后，选中恰好 F 份并调整顺序，提交锁定。服务端按冻结版式自动分页拼图，访客仅见水印总览。

订单号全站唯一，取消后仍保留。组织成员可取消、在回收站恢复、解锁重新选图；解锁保留生成消耗和全部版本历史，重新提交前暂停旧交付下载。在途请求取消后继续核对，不再发起后续生图和拼版。

## 水印与手动下载

开户时固定水印和版式；空水印使用当时的店铺显示名。后台可选择订单，预览各开户账号当前水印后批量更新。更新使旧预览地址失效，不修改原图，不调用生图。

访客的图库、头像、版本和总览均由服务端压平并加密集水印，图片每次请求校验订单状态，使用 `no-store`。访客页面没有原图切换、目录写入或图片持久化功能。

打开页面和生成完成都不会自动下载。后台主动点击下载后选择根目录，每单保存到 `订单号_备注` 文件夹；无备注时只有订单号。非法字符会替换，过长名称按字节限制并消歧；服务器备注保持原样。下载清单和 ZIP 只包含最终打印拼图，不含单张结果或水印预览。不支持目录授权时使用 ZIP。

目录写入校验文件哈希及管理归属，未经系统管理的同名文件不会被覆盖。工作台仅显示待制作与选图中的订单；历史订单展示全部当前客户订单，提交或取消后在这里查阅。旧流程订单数据仍保留在后端兼容模型中，当前页面不再显示旧流程列表。打印文件需手动下载。

订单弹窗显示买家和卖家备注，后台可修改卖家备注；已提交订单会自动重新排版。打印标题使用订单号及卖家备注，下载文件夹的后缀使用内部备注，两者不要混用。

## 验证与发布

```sh
npm test
npm run build
npm run test:e2e
```

回归使用临时数据库和模拟生图服务，不产生真实生图费用。浏览器回归端口为 8001、5174。

发布使用 [迁移审计脚本](deploy/audit_framework.py) 在隔离副本上验证组织迁移、幂等性、历史记录及原图哈希，再核对在途任务、停止服务、备份并切换。**不以本地数据库覆盖生产数据**。旧代码不兼容新角色和订单模型，回退需遵守 [备份与回退边界](deploy/framework-release.md)。

## 后台使用说明与维护

登录后台后，点击“使用说明”阅读和搜索操作指南。所有有效后台账号可阅读，正文由 `/api/staff-guide` 校验后台会话后提供；访客和未登录用户无法读取。正文源文件为 `backend/content/staff-guide.json`，不会打包到公共前端资源。

每次功能变化必须同步更新对应说明、版本、日期和更新记录，规则见 [AGENTS.md](AGENTS.md)。`npm test` 已包含漏改检查；也可单独运行 `npm run check:docs`，跨提交审查时加 `-- --base <基础提交或分支>`。检查无法代替内容审查，不能只更新时间而不修改行为说明。
