# AI 头像贴纸工作台

本机运行的内部生产网站：批量头像和模板套装、生图队列、透明打印排版、中文水印总览、结果检查、账号和管理设置。

## 启动

需要 Node.js 22.12+、npm 和 uv。首次安装依赖：

```sh
npm run setup
```

日常启动：

```sh
npm start
```

打开 **http://127.0.0.1:8000**。在终端按 Ctrl+C 停止服务。命令只监听本机，不部署到服务器。

开发时使用 `npm run dev`，页面地址为 http://127.0.0.1:5173。修改后端代码后重新启动开发命令；前端自动刷新。可复制 `.env.example` 为 `.env` 调整端口、数据目录或水印字体。

## 第一次使用

1. 创建管理员账号；此入口只在尚无账号时出现。
2. 在「管理设置」填写网站专用 FAL API Key 并保存。旧 OpenAI 密钥不会被当作 FAL 密钥使用。密钥保存后只显示配置状态；留空不会覆盖原密钥。缺少密钥时任务保持排队。
3. 在「模板库」新建套装：填写唯一编号、名称和男孩／女孩分类，上传恰好 12 张图片；按文件名自然排序后可逐张调整顺序。编辑生成新版本，旧订单继续使用原版本。
4. 在「账号设置」填写水印文字和常用打印参数。留空水印使用显示名称。
5. 在「工作台」上传头像、修改订单名称、逐单或批量选择套装和打印参数。等待「草稿已保存」后，未提交内容可在刷新或重新打开页面时恢复。
6. 选择本机输出根目录并提交订单。任务中心分别显示服务器进度与本机保存状态；可继续添加其他订单。

上传前会在浏览器本地按短边 1024 px 等比缩小头像和新增／替换的模板；短边不超过 1024 px 时不放大，PNG／WebP 保留透明通道，原始本机文件保持原样。服务器接收处理后的图片，既有模板和结果不会批量改写。

选择模板弹窗支持按名称或编号搜索（不区分大小写），逐单与批量选择都可用。搜索隐藏套装时仍保留已有选择，可清空搜索继续查看。

需要新增制作成员时，在管理设置生成邀请码。邀请码七天有效、只能使用一次。成员只访问自己的订单和文件；管理员可以管理账号与公共模板。API 接口也校验账号归属和当前页面预期账号，避免多标签页切换账号后误提交。

## 生成、检查与恢复

- 通过 FAL 队列调用 `openai/gpt-image-2/edit`，使用 FAL 账号和密钥；固定 `low`、`1024×1024`、透明 PNG、每次一张，模板在前、头像在后。无需 OpenAI API Key。
- 每套产生 12 个独立任务。管理设置仅保留「最大同时处理数量」，默认 2，可设 1–40；不配置每分钟生图数量。网站所有账号共用上限，包含已提交、在 FAL 排队和正在处理的任务。FAL 账号本身另有跨应用共享的实际并发上限，达到时由 FAL 排队等待。
- 默认 A4、300 DPI、单张透明内容长边 85 mm、10 mm 页边距和间距。亮度和色彩平衡默认关闭。
- 「结果检查」对照原头像、固定模板、当前结果；单张重跑仅生成这一张，成功后更新所属套装和总览。失败保留旧结果。
- 已生图但抠图失败时，配置抠图服务后点击「仅重试后处理」，复用已保存原始结果。它不会再次调用 FAL 生图。
- 「重新排版」只处理已有图片；修改账号水印后，打开需要更新的订单点击「更新水印」，打印文件保持原样。
- 暂停影响尚未开始的任务。关闭网页后，本机后端进程继续处理；关闭终端或电脑会停止服务。重启恢复排队任务；已取得 FAL 请求编号的任务继续查询同一个请求，结果下载失败也重新取回原结果。已发送但没有取得编号的未知请求不会自动重发。
- 单张结果显示 FAL 排队／生成状态和请求编号。连接异常时优先恢复原请求；「重新生成」会产生新的计费请求，尚未确认结束的 FAL 请求不能直接重跑。

## 文件保存

Chrome／Edge 优先使用目录授权；不支持该能力的浏览器在订单详情下载 ZIP。ZIP 保留相同目录结构。

```text
输出根目录/
└── 小满/
    ├── 小满_B001_1.png
    ├── 小满_B001_2.png
    └── 小满_水印总览.png
```

套装独立排版、页码从 1 开始，打印 PNG 无水印。A4 为 2480×3508 px 并含 300 DPI 元数据；打印时选择 100%／实际尺寸。

一个头像只输出一张全部套装总览：每套 4×3、每单元 256 px、多套纵向排列、白底中文水印。单张成品保留在服务器，可以单独下载。

网页关闭期间不能写入本机目录。重新打开后检查授权和文件校验值，补齐遗漏或旧版本；未完成全部套装时显示「已保存当前成品，等待其余图片」。

本地同名文件未经此订单管理时，选择其他目录；不会直接覆盖。已管理文件被修改或损坏时，订单详情的「修复此订单已管理的文件」会在确认后恢复服务器版本。更新完成且逐一校验后，才删除该订单淘汰的旧页。多标签页写入同一订单目录会串行执行。

## 数据与备份

正式数据在被 Git 忽略的 `.data/`：账号、密钥、任务、原始上传、模板版本、结果和文件清单。首版不自动清理素材。备份时先停止应用，再完整复制 `.data/`，恢复时完整放回；不要只复制 SQLite 主文件而遗漏 WAL 或图片目录。

浏览器草稿、目录授权句柄和本机文件管理记录存储在该浏览器的 IndexedDB，按账号隔离。清除浏览器站点数据后需要重新选择目录；原有服务器结果仍保留。同名但已失去管理记录的本地文件按外来文件处理。

## 验证

```sh
npm test
npm run build
npx --prefix frontend playwright install chromium
npm run test:e2e
```

自动测试使用临时数据目录和注入的测试生图服务，覆盖真实上传、后台处理、排版和浏览器操作；不会污染正式账号或调用付费 API。浏览器测试使用 8001、5174 端口。

详细范围和限制见 [验收记录](docs/verification.md)，后端接口和环境参数见 [backend/README.md](backend/README.md)。真实 FAL／椰子抠图服务和打印机实打效果，待填写密钥及连接打印机后验证。

FAL 接口依据：[编辑模型参数](https://fal.ai/models/openai/gpt-image-2/edit/api)、[异步队列](https://fal.ai/docs/documentation/model-apis/inference/queue)、[并发限制](https://fal.ai/docs/documentation/model-apis/concurrency-limits)。
